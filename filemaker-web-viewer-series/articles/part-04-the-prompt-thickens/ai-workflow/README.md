# AI Workflow Packet

This packet preserves the Article 4 development loop in order. Browser harnesses support rapid renderer inspection; only explicitly labeled native FileMaker evidence supports claims about layouts, portals, scripts, bridge behavior, records, and acknowledgement state.

1. [`01-human-brief.md`](01-human-brief.md) defines the human-owned outcome and constraints.
2. [`02-context-manifest.md`](02-context-manifest.md) records the source and contracts supplied to the AI.
3. [`03-initial-prompt.md`](03-initial-prompt.md) preserves the initial request.
4. [`04-initial-output/`](04-initial-output/) contains the first proposed page, renderer, and browser harness.
5. [`05-review-notes.md`](05-review-notes.md) evaluates the proposal.
6. [`06-native-test-evidence.md`](06-native-test-evidence.md) records native FileMaker test results.
7. [`07-revision-prompt.md`](07-revision-prompt.md) turns observed failures into the next bounded request.
8. [`08-final-change/`](08-final-change/) contains the reviewed change and browser harness from that pass.
9. [`09-acceptance-results.md`](09-acceptance-results.md) records acceptance results.
10. [`10-redesign-brief.md`](10-redesign-brief.md) defines the subsequent redesign.
11. [`11-redesign-output/`](11-redesign-output/) contains browser previews and the revised module source.
12. [`12-redesign-test-evidence.md`](12-redesign-test-evidence.md) records the redesign test evidence.

Additional PNG captures in this directory are native performance and interaction evidence. Their surrounding evidence documents govern the claims they support.
